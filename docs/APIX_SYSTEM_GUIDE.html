1 Cloud Function & Scheduler Setup

APIX uses Google Cloud Scheduler and Cloud Tasks to automate two operations:

OperationTriggerFrequencyPurpose
Fee Distribution Cloud Scheduler Weekly (Sunday midnight UTC) Distribute accumulated USDC fees to builders & team
Token Graduation Cloud Tasks On-demand (threshold crossed) Deploy Merkle root + liquidity on-chain

How Fee Distribution Works

Cloud Scheduler (weekly cron: 0 0 * * 0) | v POST /internal/trigger-fee-distribution (Backend on Cloud Run) | +---------------------+ | | v v fee-distribution-evm fee-distribution-solana (Cloud Function) (Cloud Function) | | v v On-chain TX On-chain TX | | +---------------------+ | v POST /internal/fee-distribution-confirm (Backend clears pending fees)

How Graduation Works

API call crosses graduation threshold | v Cloud Tasks Queue (dedup by named task: graduate-{addr}) | v POST /internal/graduate/:tokenAddress (Backend builds Merkle tree from earnings) | +---------------------+ | | v v graduation-evm graduation-solana (Cloud Function) (Cloud Function) | | v v POST /internal/graduation-confirm/:tokenAddress (Backend marks graduated = true)

The 4 Cloud Functions

All source code lives in cloud-functions/:

Fee Distribution EVM

cloud-functions/fee-distribution-evm/

Calls TokenDistributor.distributeFees() on-chain to split accumulated USDC among builders and team.

HTTP Weekly

Fee Distribution Solana

cloud-functions/fee-distribution-solana/

Calls distribute_fees instruction per token on Solana. Splits fees among builder, team, and buyback.

HTTP Weekly

Graduation EVM

cloud-functions/graduation-evm/

Calls graduateTokenWithMerkle() with Merkle root, then distributes fees. Gas limit: 25M (Uniswap V4 pool init needs ~20M).

Cloud Tasks On-demand

Graduation Solana

cloud-functions/graduation-solana/

Two steps: graduate_with_merkle() then distribute_fees(). Uses Borsh encoding for Merkle root.

Cloud Tasks On-demand

Setup Steps

  1. Deploy Cloud Functions 
    # Quick: use the deployment script
./deploy-cloud-functions.sh

# Or manually per function:
gcloud functions deploy graduateEvm \
  --gen2 --runtime=nodejs20 --region=us-central1 \
  --trigger-http --allow-unauthenticated \
  --set-secrets="AUTOMATION_PRIVATE_KEY=automation-private-key:latest" \
  --set-env-vars="RPC_URL=https://sepolia.base.org,..."
  2. Create Cloud Tasks Queue 
    gcloud tasks queues create graduation-queue --location=us-central1
  3. Set Up Cloud Scheduler 
    gcloud scheduler jobs create http fee-distribution-weekly \
  --schedule="0 0 * * 0" \
  --uri="https://your-backend.run.app/internal/trigger-fee-distribution" \
  --http-method=POST \
  --headers="Content-Type=application/json,X-Fee-Distribution-Secret=YOUR_SECRET" \
  --time-zone="UTC"
  4. Configure Backend Env Vars (on Cloud Run)
    GRADUATION_QUEUE_NAME=graduation-queue GRADUATION_QUEUE_LOCATION=us-central1 GRADUATION_FUNCTION_EVM_URL=https://graduateevm-xxxxx.run.app GRADUATION_FUNCTION_SOLANA_URL=https://graduatesolana-xxxxx.run.app FEE_DISTRIBUTION_EVM_URL=https://distributefeesevm-xxxxx.run.app FEE_DISTRIBUTION_SOLANA_URL=https://distributefeessolana-xxxxx.run.app GRADUATION_INTERNAL_SECRET=your-graduation-secret FEE_DISTRIBUTION_SECRET=your-fee-distribution-secret
  5. Or: Run the all-in-one script 
    ./deploy-gcp.sh  # Creates queue, deploys functions, configures scheduler

Backend Internal Endpoints

EndpointTriggered ByAuthWhat It Does
POST /internal/trigger-fee-distribution Cloud Scheduler X-Fee-Distribution-Secret Fetches tokens, groups by chain, calls fee distribution functions
POST /internal/graduate/:tokenAddress Cloud Tasks X-Graduation-Secret Builds Merkle tree, invokes graduation Cloud Function
POST /internal/graduation-confirm/:tokenAddress Cloud Function callback X-Graduation-Secret Marks token graduated = true
POST /internal/fee-distribution-confirm Cloud Function callback X-Fee-Distribution-Secret Clears pendingFeesForDistribution
GET /internal/graduation-earnings/:tokenAddress Solana Cloud Function X-Graduation-Secret Returns earnings breakdown for batch mint

Race Condition Protection (3 Layers)

Layer 1 — Cloud Tasks Deduplication: Named task graduate-{tokenAddress} — duplicate dispatch returns gRPC ALREADY_EXISTS (silently ignored).

Layer 2 — Firestore Atomic Transaction: incrementVirtualDistributedWithEarnings() — single transaction caps distribution at threshold.

Layer 3 — Graduation Lock: Firestore document with 5-minute TTL — prevents concurrent graduation execution.

3 API Token Generation Mechanism

APIX uses a bonding curve token model: API usage generates tokens for callers. Tokens are tracked virtually off-chain (Firestore) during bonding, then distributed on-chain via Merkle proofs at graduation.

Phase 1: Token Creation

A two-step registration flow:

  1. Validation — Frontend calls POST /api/register without tokenAddress. Backend validates slug uniqueness, API reachability (200 status), and no duplicates. Nothing is stored yet.
  2. On-chain + Registration — Frontend creates the token on-chain (IAOTokenFactory.createToken() for EVM, create_token for Solana), then calls POST /api/register with the tokenAddress. Backend stores the token entry in Firestore.

Stored Token Entry (Firestore)

{
  "id": "0xTokenAddress",
  "slug": "my-api-server",
  "name": "My API Token",
  "symbol": "MYAPI",
  "chainId": "84532",
  "builder": "0xBuilderAddress",
  "paymentToken": "0xUSDC",
  "apis": [

      "fee": "10000", "method": "POST" }
  ],
  "virtualTokensDistributed": "0",
  "distributionModel": "merkle",
  "graduated": false
}

Phase 2: Bonding Curve (API Calls Earn Tokens)

"Pay After Success" Flow

User Backend Proxy Builder API | | | |-- API request --------->| | | + PAYMENT-SIGNATURE | | | header (base64 JSON) | | | |-- Verify payment ------->| (no settle yet) | | (sig, amount, recipient)| | | | | |-- Forward request ------>| | | + X-IAO-Auth JWT | | | | | |<-- Response (2xx) -------| | | | | |-- Settle payment ------->| (NOW charge user) | | | | |-- Accrue tokens -------->| (fire-and-forget) | | | |<-- API response --------| | | + payment receipt | |
Key principle: Users are only charged if the builder API returns a 2xx status.

Token Calculation

tokensEarned = (fee × paymentTokenPrice) / (10 ^ paymentTokenDecimals)

Example:

  • API fee: 10000 (0.01 USDC, 6 decimals)
  • paymentTokenPrice: 25,000,000,000,000,000,000,000 (25,000 tokens per USDC)
  • paymentTokenDecimals: 6
  • Result: 250 tokens (with 18 decimals)

Atomic Firestore Update

After payment settles, incrementVirtualDistributedWithEarnings() updates two collections in a single Firestore transaction (no race conditions):

iao-tokens/{tokenAddress}

  • virtualTokensDistributed += tokensEarned capped at threshold
  • totalFeesCollected += fee
  • pendingFeesForDistribution += fee

token-earnings/{addr}#{user}

  • totalTokensEarned += tokensEarned
  • totalFeesPaid += fee
  • callCount += 1

Graduation Thresholds

ChainThresholdRaw Value
EVM (Base Sepolia)625,000,000 tokens625000000000000000000000000 (18 dec)
Solana (Devnet)625,000,000 tokens625000000000000000 (9 dec)

The threshold = 62.5% of 1 billion total supply. Can be overridden with TEST_GRADUATION_THRESHOLD env var.

Phase 3: Graduation

When virtualTokensDistributed ≥ graduationThreshold:

  1. Dispatch — graduationDispatcher.ts creates a named Cloud Task (graduate-{tokenAddress})
  2. Lock — Backend acquires Firestore graduation lock (5-min TTL)
  3. Build Merkle Tree — From all token-earnings entries for this token
  4. Store tree in Firestore merkle-trees/{tokenAddress}
  5. Invoke Cloud Function — Sets Merkle root on-chain + deploys liquidity (Uniswap V4 for EVM, Raydium CLMM for Solana)
  6. Confirm — Cloud Function calls back, backend sets graduated: true

Solana Leaf Hash

keccak256(keccak256(
  pubkey_32bytes || amount_u64_le
))

EVM Leaf Hash (OpenZeppelin)

ABI.encode(
  ['address', 'uint256'],
  [userAddress, amount]
)

Phase 4: Claiming

  1. Get proof — GET /api/earnings/:serverSlug/:userAddress returns { totalTokensEarned, merkleProof[], merkleIndex }
  2. Submit claim on-chain — EVM: IAOTokenV2.merkleClaim(amount, proof) / Solana: merkle_claim instruction
  3. Backend updates — Sets claimed: true and claimTxHash in token-earnings

Fee Distribution (Weekly)

  1. Cloud Scheduler triggers POST /internal/trigger-fee-distribution
  2. Backend groups non-graduated tokens by chain
  3. Calls fee distribution Cloud Functions
  4. On-chain split: builder share + team share + buyback
  5. Callback clears pendingFeesForDistribution
